# 标题
从零做Agent12：改了一行，变好了吗？

# 正文
改了提示词里的一句话，跑一次，好了。是这句话的功劳，还是运气？第12集讲怎么测试一个 Agent👇

📋 评测的几个词
任务：一道固定的题。试验：把题做一次，模型每次不一样，要做好几次。评分器：一小段代码，看结果，不看它说了什么。轨迹：一次运行完整的记录，分数告诉你对不对，轨迹告诉你为什么。

📖 Anthropic 的文章和 Claude Code 文档
文章建议：从真实的失败里找 20 到 50 个简单任务，能用代码判的就用代码判，再靠人读轨迹。Claude Code 有 claude -p、json 输出、轮数和费用上限、调试开关，但文档没有给你自己任务用的测试框架，要自己搭。

🛠 我们怎么做的
4 道固定的题，每次试验从干净的项目拷贝开始，整串消息存成文件，评分器看结果，最后一张表。一次只改一处。20 项检查，不用 API key。

🧪 真实测试（DeepSeek，我们自己的小测试，每种 5 次，共 40 次）
改动只有一句话：“改一个值时，搜索整个项目，别的地方也一起改”。
· 不加这句话：20 次全对。加了：18 次对
· 读掉的 token：改版本号平均从 13,918 到 18,040，改税率从 13,822 到 19,240。每次差得很大，是线索，不是证明
· 结论：没帮上忙。题太容易，不加已经全对，看不出进步
· 读了两条失败的轨迹：一次是它把更新日志里第一版的记录并掉了；一次是第一条命令被权限规则拒绝，它就停了。各 1/5，证据很弱

⚠️ 一个真实的坑
试跑时我们自己的评分器，把对的判成了错：Agent 让横幅去读配置里的版本号，运行结果是对的，评分器却要一模一样的字。后来改成运行程序，看它打印什么。

⚠️ 没做的
用另一个模型打分、几十道题的大题库、每次改动自动跑、更难的题。
