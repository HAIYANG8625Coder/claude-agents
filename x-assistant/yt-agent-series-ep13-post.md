# Description
做完十三集，我们的 Agent 能日常用了：一个聊天循环，把前十二集的部分接在一起。这一集讲怎么接，用一次真实的终端演示，再用 30 次真实运行测一测，最后复习第1到13集，并说一下下一个系列的计划。

聊天循环、流式、会话
聊天循环：读一行，运行，打印，再等下一行。流式输出：模型写答案时，收到一段显示一段。会话：整段对话存成文件，下次接着聊。斜杠命令：以斜杠开头，是给程序的命令。中断：按 Ctrl 加 C，停掉这一轮，聊天还在。

官方文档里的样子
Claude Code 文档：循环三步，收集信息，动手，检查结果，你随时可以打断；Esc 停掉这一轮；会话写进一个文本文件，可以继续上一次，或者选一次旧的；斜杠命令很多；检查点只记文件编辑工具改的文件，不是 git 的替代。Anthropic 的流式文档：事件按顺序来，文字走文字增量，工具调用走 json 增量，攒齐了再解析。

我们自己做的
引擎里，运行一次可以接着一个已有的对话，模型调用打开流式就把文字交给显示，消息是普通的字典，整个对话直接存成文件。聊天循环在另一个文件里：每一轮存盘，12 个斜杠命令，Ctrl+C 停掉这一轮。前面的权限，上下文，任务清单，子 Agent，记忆，hook 和 skill 都接进来了。常驻那一集的程序共用引擎，没有放进聊天里。共 1,486 行代码（含注释和空行），38 项检查，不用 API key。

真实演示和真实测试（DeepSeek 模型，只是我们自己的小测试，每种 5 次，共 30 次）
· 税率改对：保留聊天和每题从零开始，都是 5 次全对。“你改了哪些文件”：保留聊天 5 次全对，从零开始 0 次
· 读掉的 token：101,105 对 88,425，每次差得很大，不能说谁更费，谁更省
· 屏幕上出现第一个字：流式平均 5.1 秒，不流式 7.04 秒；整段写完的总时间 7.44 对 7.04 秒
· Ctrl+C 之后的下一个问题：有修复 4 次答对，没有修复 0 次（接口拒绝）；新进程里接上上一次：5 次答对。Ctrl+C 是代码模拟的，只测了工具调用刚出现的那一刻

一个真实的坑
Ctrl+C 让对话停在半路：模型要调用一个工具，结果还没来，下一个问题就被接口拒绝。修复：先给每个没跑完的调用补一个结果。另有两个小问题：5 次里有 1 次，模型把“被用户停掉了”当成最后的答案；关掉流式的第一版什么也没打印。

Claude Code 有的，我们没有
来自官方文档：系统层面的沙箱（默认不开），自动权限模式，子 Agent 文件，检查点和回退，会话选择器和分叉，更完整的输入编辑，企业的统一设置，云端会话。

我打算做企业级的 AI Agent：身份和策略，隔离，审计和成本，可靠性，部署。这只是计划，细节会改。
