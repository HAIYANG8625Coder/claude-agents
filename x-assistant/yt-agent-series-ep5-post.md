# Title
从零到1做Agent第5集：上下文｜数 token、清旧结果、压缩
# Description
Agent 越跑越长，窗口怎么不爆？
这一集给 Agent 加上下文管理：数 token，先清旧结果，再压缩。

数 token
· 用 API 每轮返回的数，不靠猜
· 用 DeepSeek 的接口时，第二次调用 input_tokens 只有 225，窗口其实是 1,633，因为 1,408 个来自缓存。官方文档说缓存的前缀也占窗口，所以要把缓存读取、缓存写入一起加上

两招
1. 清旧结果：最新 3 个工具结果原样保留，更早的换成一句话（Anthropic 的工程文章说这是最轻的压缩方式之一）
2. 压缩：超过线，让模型把旧的几轮写成总结，最近 4 轮原样保留，任务和笔记一起带上。总结是同一个模型写的，不说它和 Claude Code 的一样好

真实测试（DeepSeek 模型，24 个文件，每种设置 3 次）
· 什么都不管：25 轮，峰值约 25,000 token，3/3 答对
· 只清旧结果：峰值 8,800 到 11,500，3/3 答对
· 只压缩：峰值 12,700 到 12,900，3/3 答对
· 两个一起：峰值 8,900 到 10,900，2/3 答对，另一次跑满 60 轮没有答案
3 次太少，不能说哪种最好

三个坑
1. 清掉了唯一的记录：第一版只清旧结果，模型忘了找到的待办，从头再读，跑满 60 轮。系统提示里加一句“发现了什么，先写在自己的回复里”后，3 次都答对，但有一次跑了 53 轮才答对
2. 总结会丢早期的详细指令（官方文档提醒，我们没测到），长期规则写进笔记文件
3. 一个输出特别大，总结以后窗口又满：官方文档说 Claude Code 试几次就会停止自动压缩并报错，大输出要在工具里截断
