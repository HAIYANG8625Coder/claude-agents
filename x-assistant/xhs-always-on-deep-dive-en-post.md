# 正文
上一条中文版的英文版来了：同样照着 Anthropic 11月13日的官方文章《Building always-on agents》一节一节拆，这次是英文讲解 + 中文字幕，想练英文听力、顺便学 Agent 的可以看这版 🎧

💡 最反直觉的一点
「一直在线」只是用户的感受。它大部分时间在睡觉，一个 token 都不花；事件来了才醒，跑一小段（run），写回状态再睡

🧩 五个部件（英文原词）
① Event inbox 收件箱：事件先写进数据库表，一个收件箱同一时间只有一个 worker
② Timers 定时器：定时器自己不开跑，到点只往收件箱写一条事件
③ Memory 记忆：一个文件夹，只存查不回来的东西
④ Permissions 权限：风险最大的地方。密钥放在外面的代理里，要你批准时 run 先停
⑤ Outbox 发件箱：发、不发、或者问你；一开始宁可少发

🛠 我照着做了一个
替我盯小红书笔记数据的 Agent：收件箱是 SQLite 表，闹钟是 launchd，记忆是 4 个文件，值得说才发 Telegram。视频结尾有它发给我的真实消息。代码开源在 GitHub，地址在评论区

📝 说明：文中的数字是模型成本：长程编程测试上 Opus 5.5 每解一题比 Opus 5 少花 78%，普通任务少 40%
