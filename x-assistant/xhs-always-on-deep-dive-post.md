# 标题
Anthropic官方：Always-on Agent逐节拆解

# 正文
11月13日，Anthropic 官网发了一篇文章《Building always-on agents》，讲怎么做一个一直在线的 Agent：不用你开口，自己盯着事情，到点干活，做完来找你。这期照着原文一节一节拆，原图都放在视频里 👇

💡 最反直觉的一点
「一直在线」只是用户的感受。它大部分时间在睡觉，一个 token 都不花；事件来了才醒，跑一小段（文章叫一次 run），写回状态再睡

🧩 五个部件
① 收件箱：事件先写进一张数据库表，handler 写表、叫醒 worker。同一时间一个收件箱只有一个 worker，不会抢跑；表说了算，worker 崩了换一个重试
② 定时器：分「跟进」（Agent 自己定）和「日程」（用户定）。定时器自己不开跑，到点只往收件箱写一条事件
③ 记忆：一个文件夹。用户指示、索引、已经说过的话每次都读；笔记和任务进度只读索引。只存查不回来的东西
④ 权限：文章说这里风险最大。密钥不交给 Agent，由外面的代理填上；要你批准时 run 先停，你的回答变成新事件回到收件箱
⑤ 发件箱：三种结局：发消息、不发、停下来问你。发多少用评测来调，一开始宁可少发

🛠 我照着做了一个
替我盯小红书笔记数据的 Agent：收件箱是一张 SQLite 表，闹钟是 launchd，记忆是 4 个文件，值得说才发 Telegram。视频结尾有它发给我的真实消息。代码开源在 GitHub，地址在评论区
