# Title
从零到1做Agent第12集：测试和调试｜改了一行，Agent 变好了吗？
# Description
改了提示词里的一句话，跑一次，好了，就上线？这一集讲怎么知道一次改动有没有用：评测的几个词，Anthropic 文章和 Claude Code 文档怎么说，我们自己做的一个小测试框架，再用 40 次真实运行测一句话，最后复习第1到12集。

评测的几个词
任务是一道固定的题。试验是把题做一次，模型每次不一样，所以要做好几次。评分器是一小段代码，看结果，不看 Agent 说了什么。轨迹是一次运行完整的记录：分数告诉你对不对，轨迹告诉你为什么。

文章和 Claude Code 里的样子
Anthropic 工程博客 2026 年 1 月 9 日的文章建议：从真实的失败里找 20 到 50 个简单的任务，能用代码判的就用代码判，再靠人读轨迹。任务很多次都是零分，多半是题或评分器坏了；测试已经接近百分之百，只能防退步，看不出进步。Claude Code 里有 claude -p、json 和 stream-json 输出、轮数和费用上限（费用是估算）、调试开关、安全模式，还有一个文档写明给评测用的开关。会话记录的格式是内部的，版本之间会变，所以要测试就自己存一份。文档没有给你自己任务用的测试框架。

我们怎么做的
4 道固定的题；每次试验从干净的项目拷贝开始；评分器看结果；整串消息存成文件；最后一张表；一次只改一处。20 项检查，不用 API key。

真实测试（DeepSeek 模型，只是我们自己的小测试，4 道题 × 2 种做法 × 5 次 = 40 次）
改动只有一句话：“改一个值时，搜索整个项目，别的地方也一起改”。
· 不加这句话，20 次全对；加了，18 次对（改版本号 4/5，加折扣函数 4/5）
· 读掉的 token：改版本号平均从 13,918 到 18,040，改税率从 13,822 到 19,240。每次差得很大，是线索，不是证明
· 没帮上忙：题太容易，不加已经全对，看不出进步
· 两条失败的轨迹：一次它把更新日志里第一版的记录并掉了；一次第一条命令被权限规则拒绝，它就停了。各 1/5，证据很弱

一个真实的坑
试跑时，我们自己的评分器把对的判成了错：Agent 让横幅去读配置里的版本号，结果是对的，评分器却要文件里一模一样的字。后来改成运行程序，看它打印什么。

没做的
用另一个模型打分、几十道题的大题库、每次改动自动跑、更难的题。
