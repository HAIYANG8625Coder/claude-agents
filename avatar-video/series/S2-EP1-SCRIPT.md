【开场】
1. 两个人，同时用同一个 Agent。lin 问的是自己项目的代号。我们测了五次，五次拿到的，都是另一个人 sam 的。这是我们自己写的第一版服务。测试里，sam 只比 lin 晚零点五秒发问。
2. 这是第二季第一集：多人共用一个 Agent。Agent，就是会自己调用工具干活的 AI 程序。今天回答三个问题：为什么会串，怎么修好，修好之后还有什么没挡住。串数据，重启，越界，这几个测试用 DeepSeek 真实跑，一共二十五次。

【01 问题】
3. 第一季做的 Agent，是给一个人用的。谁启动它，谁就是用户。它在当前这个文件夹里干活，对话也只属于这个人。
4. 现在在它前面加一个一直开着的服务程序，让很多人一起用。马上缺三样东西。第一，是谁在问。第二，在谁的文件夹里干活。第三，接着的是谁的对话。

【02 概念】
5. 先讲几个词。服务，是一个一直开着的程序，同时回答很多人的请求。就像一个前台，大家都来这里办事。
6. 怎么知道是谁？每人拿一个 token。这里的 token，是一串很长的随机字符，当通行证用。它和模型计费的那个 token 不是一回事。服务认出它，就能找到这个人的文件夹，和这个人的对话。
7. 再说进程和线程。进程，就是一个正在运行的程序。进程像一间单独的房间，里面的东西是自己的。线程像同一间房里的几个人，桌上的东西大家共用。共用省事，但也会互相改到。
8. 会话，就是存下来的一段对话。在我们这里，它是硬盘上的一个文件。下次接着聊，就是把这个文件读回来。

【03 系统架构】
9. 先看整张图。整个系列要做的系统有几部分。认人的服务，和干活的引擎。还有管权限的规则，关住命令的沙盒，藏模型 key 的代理，和审计日志。这一集只做前两部分：服务是新写的，引擎用第一季的。其余的后面几集补。
10. 一个请求是这样走的。用户把任务发给服务。服务认出是谁，交给引擎。引擎问模型，下一步做什么。模型说要读文件，引擎就去项目文件夹里读。读哪个文件夹，靠引擎记住的一个变量。
11. 第一版我们图省事。服务里只有一份引擎，两个请求各开一个线程。看起来像两个 Agent 在干活，对话也确实是分开的。但那个文件夹变量只有一份。后来的请求一改它，先来的请求就读错了文件夹。
12. 那每人一台电脑，会不会这样？这个问题不会。每台电脑上的 Agent，各有各的内存。问题出在很多人共用同一个程序，里面又有大家共用的东西。如果几台电脑共用一个网盘或数据库，那里还是要小心。

【04 官方文档】
13. 先看官方怎么说。Anthropic 有个开发包，叫 Agent SDK。它在后台启动 Claude Code 来干活。我们的引擎没用它，这里拿来对照。它的部署文档写着：一个会话，对应一个子进程。子进程，就是你的程序另外启动的进程。想让会话各用各的工作文件夹，就给每个会话单独指定。能同时开多少个，要看机器的内存。
14. 身份在哪里检查？同一页建议：认证放在 Agent 前面的网关上。认证，就是确认你是谁。网关，就是挡在前面的一道门卫。到 Agent 这里的，应该是已经认证过的请求。不该由 Agent 自己去验用户的 token。
15. 对话存在哪里？默认在本机硬盘上。容器，就是装着程序运行的独立小环境。文档说，容器重启，机器减少，或者换一台机器，这些内容就没了。要接着用，得把对话记录同步到外部存储。这种同步只管对话记录，而且不保证成功。发不过去的那一批，会被丢掉。

【05 我们的代码】
16. 现在看我们的版本。一个很小的服务，站在引擎前面。引擎就是第一季的 Agent，它的代码一行没改。新代码一共大约三百七十行。
17. 第一件事，先认人。没有 token，或者 token 不对，返回四零一。拿别人的会话编号来用，返回四零四，和这个编号根本不存在一样。这样别人连编号对不对，都试不出来。四零一是没认出你，四零四是找不到。
18. token 只存哈希，就是它的数字指纹。数据库就算被看到，也还原不出原文。项目名只能指向自己文件夹里的东西。管理员能发 token 和收回 token，但只管自己的团队。
19. 第二件事，每条消息，开一个新进程跑引擎。文档是一个会话一个进程，我们更简单，一条消息一个。进程在这个用户的项目文件夹里启动。环境变量，就是程序启动时带进来的设置。这里从零开始拼，只放我们指定的几样。服务那边别的设置，带不进去。
20. 第三件事，读回对话，跑一轮，再存回去。先写一个新文件，再整个换掉旧的，不会只存一半。这一集还没配权限规则，所以用只读模式。能读文件，也能跑几条看内容的命令。不需要模型的检查有十七条，全部通过。其中四条通过，代表问题确实存在。

【06 怎么测】
21. 怎么测？两个用户，lin 和 sam，各有一个项目文件夹。每个文件夹里放一个代号文件。两个人的代号不一样，是我们随便起的。
22. 第一个测试：两人几乎同时问，读代号文件，把代号告诉我。sam 比 lin 晚零点五秒。回答里是自己的代号，算对。看到了别人的代号，算串了。
23. 对比两种做法。朴素版，就是刚才那个第一版，每个请求开一个线程。进程版：每个请求开一个进程。每种跑五次，每次有两个人的回答。
24. 还有两个测试。一个测重启：让它记住一个词，重启服务，再问是什么。分两组：对话文件留着，或者删掉。每组五次，答出这个词才算记得。一个测越界：用进程版，也跑五次。给 lin 的 Agent 一个路径，让它看 sam 的文件。读到了 sam 的代号，就算越界。

【07 结果】
25. 先看结果。朴素版，lin 问了五次，五次拿到的都是 sam 的代号，其中两次顺带提了一句文件夹不对。sam 五次都拿到自己的。进程版，十个回答全是自己的，别人的代号一次也没出现。
26. 为什么会这样？就是架构图里那个变量。朴素版的两个线程，共用这一个。第一步，lin 的请求进来，变量指向 lin 的文件夹。引擎去问模型，开始等。第二步，sam 的请求进来了，变量被改成指向 sam。
27. 第三步，模型回话了：让 lin 这边去读代号文件。第四步，引擎按这个变量去找文件，读到的是 sam 的。请求照样返回成功，服务没有报警。进程版里，每个进程有自己的一份，改不到别人。
28. 再看重启。对话文件还在的时候，五次全部答对，一个工具都没调用。
29. 然后只删掉对话文件，模拟换了机器，对话没带过去。五次里一次都没答对，服务也没有报错。它去项目里翻，用了五到十五次工具。三次开头就说不知道。另外两次，把项目里的另一个词当答案给了我们。其中一次，最后补了一句也可能不知道。
30. 要说清楚：每种只跑了五次，一个模型，我们自己的小项目。朴素版是我们故意写简单的，不代表任何产品。两个请求撞在一起，也是我们安排的。真实使用里多久撞一次，我们没有测。

【08 一个坑】
31. 一个真实的坑，这次是我们猜错了。我们以为，环境里留下的旧模型令牌，会跟着请求一起发出去。这里的令牌是给模型用的，不是用户的通行证。写成测试一跑，测试没通过。
32. 实测结果：key 由代码传进去时，旧令牌没有发出去。但代码没指定接口地址时，环境里的旧地址会生效。请求连同 key，都会发到那个旧地址。如果 key 也从环境变量读，旧令牌就会一起发出去。
33. 修法很简单：引擎进程的环境从零拼，只放它需要的几样。刚才的结果，来自 Anthropic 的 Python 开发包。版本是零点一二五，用本地假服务器测的。它不代表 Claude Code。

【09 还没挡住】
34. 现在看越界测试，用的是修好之后的进程版。五次里有四次，它用读文件的工具，被拒绝，然后停下了。
35. 剩下那一次，它直接用了一条看文件内容的命令，读到了 sam 的文件。读文件的工具会检查路径，这条命令没人检查。只读模式放行了它。提示词叫它别绕路，停不停仍是模型的选择，不是我们的保护。
36. 所以还差三样。权限规则，下一集做。沙盒，第四集做。沙盒像一个隔间，限制程序能碰什么。模型的 key 还在引擎手里，第五集处理。
37. 另外，导读之后，设计改了一处，本集代码还没用上。新设计里，命令改由服务来启动。每条命令单独放进沙盒，默认没有网络。因为实测发现，苹果系统的沙盒工具，不能在沙盒里面再开一个沙盒。

【10 结尾】
38. 合起来看。身份：靠 token 找到人。文件夹：每人一个。会话：存成文件，丢了也不会报错。进程：一个请求一个，两人同问没再串。但别人的文件，命令还读得到。还没有的：规则，沙盒，把 key 藏好。
39. 一句话：身份只回答是谁在问。能碰到什么，要靠边界来决定。我觉得，多人工具上线之前，值得先让两个人同时用一次。
40. 最后一个问题：你们团队共用的 AI 工具，知道每个请求是谁发的吗？评论区告诉我。
