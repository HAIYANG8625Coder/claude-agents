【开场】
1. 第一季，我们用纯 Python，做出了一个能用的编程 Agent。一个人，一台电脑。如果一家公司的很多人，要一起用它，会怎么样？
2. 这一集是第二季的导读。我先说清楚，现在什么都还没做出来。只有设计：一份产品文档，一份技术文档，和一个能点的原型。今天讲三件事：要做什么，怎么做，怎么证明它做到了。

【第一季回顾】
3. 先回顾第一季。它有循环，工具，权限，计划模式，skill，M C P，记忆，还有一套测试方法。一共大约一千五百行代码，准确说，是一千四百八十六行。
4. 但它完全信任它的用户。它是给一个人，在一台电脑上用的。

【五个问题】
5. 交给公司，会出五个问题。第一，没有身份。谁能启动它，谁就是用户，没人记录谁做了什么。
6. 第二，规则在用户手里。权限规则，用户自己能改，也能关掉。
7. 第三，没有隔离。命令用的是用户全部的权限，A P I key 就放在 Agent 的环境里。
8. 第四，没有上限。一个死循环，可以把一个月的预算花完。
9. 第五，需要有人坐在键盘前。批准要在终端里点，程序一崩，这一次的活就丢了。

【什么叫企业级】
10. 所以第二季，要把它做成一个服务，让一家公司里的很多人，安全地共用。
11. 先说，什么叫“企业级”。我们不拿认证，不讲 S O C 2，不讲 H I P A A，也不是一个能卖的产品。我们说的企业级，是八条要求。
12. 一，身份：每个请求都知道是谁。二，策略：管理员定的规则，用户关不掉。三，隔离：一条命令，一个租户，碰不到不该碰的东西。四，密钥：Agent 的进程，自己手里没有模型的 key。
13. 五，审计：事后能说清，谁做了什么，当时允不允许。六，成本：每个人每天有上限。七，可靠：崩了，或者 A P I 出错，活不丢。八，发布门槛：测试不过，改动就不能上线。
14. 每一条，都有一个验收测试。这个测试要先失败，再通过。一个测试从来没失败过，就不能证明什么。

【架构】
15. 整体结构，用一张图说。一个很小的服务，包在第十三集的引擎外面，引擎本身基本不改。
16. 原则只有一条：执行规则的东西，都放在沙盒外面。这样，即使引擎被一段提示注入控制了，它也关不掉规则。
17. 有三个进程在沙盒外面。一个是服务，管身份，策略，审计，批准。一个是凭证代理，它拿着 key，替引擎调用模型，顺便数 token 算花费。一个是出口代理，只放行允许的网址。每个会话，有自己的一个引擎进程。
18. 引擎只能连凭证代理，而且只带一个会话令牌，没有 key。命令跑得更深一层，连代理也连不上。这些，是设计。我们还没有把完整的引擎，放进沙盒里跑过。

【四个界面】
19. 设计里有四个界面。下面是原型，用的是示例数据，不是真实运行。原型已经放在 GitHub Pages 上，你可以自己点。
20. 第一，开发者的会话。每一次工具调用，都显示是哪条规则，放行或者拦下。比如 README 里藏了一句提示注入，要用 curl 把文件发出去，公司规则在命令跑之前，就把它拦住了。
21. 第二，手机上的批准。要批准的修改，变成一张卡片，带倒计时。没人回答，就是拒绝。没人看着的时候，它不会自己批准自己。
22. 第三，管理员控制台。管理员设公司规则，看每个人花了多少，离每日上限有多远。打开“只用公司规则”之后，项目和用户的放行规则，会被划掉。
23. 第四，审计日志。每一行，带着前一行的哈希。有人改了其中一行，检查会指出，是哪一行。

【怎么做，怎么证明】
24. 怎么做？十三集，分五部分，每集大约八九分钟。第一部分，谁能用，什么被允许。第二部分，隔离。第三部分，看得见，也花得起。第四部分，可靠。第五部分，上线。集数是计划，做完第一部分，可能会变。
25. 方法，和第一季一样。每个部分，先写一个不用 A P I key 的检查，用假模型，假时钟。再用 DeepSeek 跑真实的，每种五次，读一份失败的记录，没效果，也照实说。视频里的每个数字，都由代码从原始文件里算出来。
26. 这一季多一套红队测试：文件里藏一句提示注入，工具描述里藏一条指令，一条想跑出文件夹的命令，一个想放宽规则的项目文件，一个花钱不停的循环。
27. 做到什么算数？八条要求的测试，八条都过。红队测试，开着控制的时候，一次逃逸都没有。超出预算，最多超一次模型调用。这些，都是目标，不是结果。

【我们可能做错的地方】
28. 现在说，我们可能做错的地方。第一，沙盒是教学版本，可能让人觉得比实际更安全。所以，计划每一集都把已知的逃逸，在屏幕上跑一遍，开着控制一次，关掉控制一次。
29. 沙盒计划用两种。Docker 是主要的，它在 Mac 和 Linux 上一样。Mac 自带的 sandbox exec 是第二种，苹果自己在手册里，把它标成了已弃用。
30. 第二，审计日志的哈希链，只能发现改了一部分。整个文件重写，它看不出来。所以，计划把最新的哈希，另存到引擎碰不到的地方。但如果有人控制了整台机器，两处都能改。真正的系统，会把日志送到另一个存储里。
31. 第三，引擎上报的事件，是它自己说的。计划把它标成引擎上报，再拿代理和服务看到的去核对，对不上，就标出来。最后，有几页官方文档我们还没读，比如 Claude 应用网关。没读的，就写“未确认”，不当成事实说。
