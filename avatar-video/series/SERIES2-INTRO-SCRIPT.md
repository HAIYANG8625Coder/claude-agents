【开场】
1. 第一季，我们用纯 Python，做出了一个能用的编程 Agent。一个人，一台电脑。如果一家公司的很多人，要一起用它，会怎么样？
2. 这一集是第二季的导读。我先说清楚，现在什么都还没做出来。只有设计：一份产品文档，一份技术文档，和一个能点的原型。今天讲三件事：要做什么，怎么做，怎么证明它做到了。

【第一季回顾】
3. 先回顾第一季。它有循环，工具，权限，计划模式，skill，M C P，记忆，还有一套测试方法。核心代码大约一千五百行，准确说，是一千四百八十六行。
4. 但它完全信任它的用户。它是给一个人，在一台电脑上用的。

【五个问题】
5. 交给公司，会出五个问题。第一，没有身份。谁能启动它，谁就是用户，没人记录谁做了什么。
6. 第二，规则在用户手里。权限规则，用户自己能改，也能关掉。
7. 第三，没有隔离。命令用的是用户全部的权限，A P I key 就放在 Agent 的环境里。
8. 第四，没有上限。一个死循环，可以把一个月的预算花完。
9. 第五，需要有人坐在键盘前。批准要在终端里点，程序一崩，这一次的活就丢了。

【什么叫企业级】
10. 所以第二季，要把它做成一个服务，让一家公司里的很多人，安全地共用。
11. 先说，什么叫“企业级”。我们不拿认证，也不说自己符合 S O C 2 或 H I P A A。这也不是一个能卖的产品。我们说的企业级，是八条要求。
12. 一，身份：每个请求都知道是谁。二，策略：管理员定的规则，用户关不掉。三，隔离：一条命令，不能碰到别的团队的文件。每个团队，我们叫它一个租户。四，密钥：Agent 的进程，自己手里没有模型的 key。
13. 五，审计：事后能说清，谁做了什么，当时允不允许。六，成本：每个人每天有上限。七，可靠：崩了，或者 A P I 出错，活不丢。八，发布门槛：测试不过，改动就不能上线。
14. 每一条，都有一个验收测试。这个测试要先失败，再通过。一个测试从来没失败过，就不能证明什么。

【架构】
15. 整体结构，用一张图说。一个很小的服务，包在第一季第十三集做的那个 Agent 外面。我们叫它引擎。引擎本身基本不改。
16. 先说沙盒：它是一个盒子，限制程序能碰哪些文件和网络。再说提示注入：有人在文件里藏一句话，骗模型照做。
17. 原则只有一条：管规则的东西，都放在沙盒外面。设计上，引擎就算被骗了，也关不掉规则。
18. 有三个进程在沙盒外面。一个是服务，管身份，策略，审计，批准。一个是凭证代理，它拿着 key，替引擎调用模型，顺便数 token 算花费。一个是出口代理，只放行允许的网址。每个会话，有自己的一个引擎进程。
19. 引擎只能连凭证代理，而且只带一个会话令牌。它是只管这一次会话的临时通行证，里面没有 key。命令跑得更深一层，连代理也连不上。这些，是设计。我们还没有把完整的引擎，放进沙盒里跑过。

【四个界面】
20. 设计里有四个界面。下面是原型，用的是示例数据，不是真实运行。原型已经放在 GitHub Pages 上，你可以自己点。
21. 第一，开发者的会话。每一次工具调用，都会显示，是哪条规则放行，或者拦下。原型里有这样一个例子。项目的说明文件里，藏着一句提示注入。它要用一条网络命令，把文件发出去。公司规则，会在命令跑之前，把它拦住。
22. 第二，手机上的批准。要批准的修改，变成一张卡片，带倒计时。没人回答，就是拒绝。设计上，没人看着的时候，它不会自己批准自己。
23. 第三，管理员控制台。管理员设公司规则，看每个人花了多少，离每日上限有多远。打开“只用公司规则”之后，项目和用户的放行规则，会被划掉。
24. 第四，审计日志。哈希，就是一段内容的数字指纹。每一行，都带着前一行的指纹。有人改了其中一行，检查会指出，是哪一行。

【怎么做，怎么证明】
25. 怎么做？十三集，分五部分，每集大约八九分钟。第一部分，谁能用，什么被允许。第二部分，隔离。第三部分，看得见，也管得住花费。第四部分，可靠。第五部分，上线。集数是计划，做完第一部分，可能会变。
26. 方法，和第一季一样。每一集，先写一个检查，不用 A P I key，用假模型，假时钟。再用 DeepSeek 跑真实的，每种跑五次。我们会读一份失败的记录。没效果，也照实说。视频里的每个数字，都会由代码，从原始文件里算出来。
27. 这一季会多一套红队测试，就是我们自己扮演攻击者。五种情况：文件里藏一句提示注入；工具描述里藏一条指令；一条想跑出文件夹的命令；一个想放宽规则的项目文件；一个花钱不停的循环。
28. 做到什么算数？八条要求的测试，八条都过。红队测试，开着控制的时候，一次逃逸都没有。超出预算的部分，最多是一次模型调用的钱。这些，都是目标，不是结果。

【我们可能做错的地方】
29. 现在说，我们可能做错的地方。一共四个。第一，沙盒是教学版本，可能让人觉得比实际更安全。所以，计划每一个已知的逃逸，都在屏幕上跑一遍，开着控制一次，关掉控制一次。
30. 沙盒计划用两种。Docker，是一种把程序关进盒子里跑的工具。Docker 是主要的。在 Mac 上，它通过 Colima 来跑。在 Linux 的自动测试里，也会用它。Linux 上的行为，我们还没测过。Mac 自带的沙盒工具是第二种，苹果自己在手册里，把它标成了已弃用。
31. 第二，审计日志的哈希链，只能发现改了一部分。整个文件重写，只要新的链是完整的，它就看不出来。所以，计划把最新的哈希，另存到引擎碰不到的地方。但如果有人控制了整台机器，两处都能改。真正的系统，会把日志送到另一个存储里。
32. 第三，引擎上报的事件，是它自己说的。计划把它标成引擎上报。再拿代理和服务看到的去核对。对不上，就记成一条审计记录。
33. 第四，官方文档我们还没读完。有两组没读：Claude 应用网关，和插件与组织设置。读过的几页，我们会在屏幕上，对照原文再核一遍。没读的，就写“未确认”，不当成事实说。

【路线和结尾】
34. 路线是七个阶段，大约十六个工作时段。要先有一个，能从头跑到尾的最小版本，才拍第一集。阶段零做完以后，代码就放进公开仓库，地址在简介里。每周一集，和第一季一样的节奏。
35. 一句话带走：企业级的 Agent，还是那个循环，加上一些放在模型外面的边界。我的想法是，这些边界，模型自己说服不了。第二季，就是要把这件事证明出来。
36. 最后一个问题。如果你的公司要用 Agent，你最担心哪一件：密钥，花费，还是它乱改文件？评论区告诉我。
