【0 开场】 [封面卡]
Agent 做到第八步，忘了前面的要求，然后告诉你：全做完了。其实第十二步，根本没做。今天讲清楚两个东西：计划模式，和任务清单。它们是什么，Agent 为什么需要，再用我们自己的真实测试，看它们到底有没有用。数字都是 DeepSeek 真实跑出来的。

【1 问题出在哪】 [图 D1：没有计划的 Agent]
先回忆第一集的循环：看一眼，做一步，再看一眼，再做一步。它的计划，只存在模型的脑子里，没有写在任何地方。任务短，没问题。任务一长，对话越来越长，早先的要求，离得越来越远，容易漏掉。于是有两种事故：漏了一步；或者没做完，就说做完了。Anthropic 讲长任务的文章也提到这种事，叫它，过早宣布胜利。

【2 什么是计划模式】 [图 D2：直接开干，对比先计划]
计划模式：动手之前，先只看，不改，写出计划，你点头，才开始改。像装修，先看图纸，再砸墙。Agent 为什么需要？直接开干，一旦理解错，可能已经改了很多文件，要回头收拾。计划模式把检查，提前到改之前，纠正一句话，成本很低。它也被迫先读文件，再写计划。

【3 什么是任务清单】 [图 D3：任务清单和三个状态]
任务清单：把大任务拆成小项，每项三个状态：待做，进行中，完成。像购物清单，买一样，划一样。Agent 为什么需要？因为它没有可靠的记事本，长任务里，早先的步骤会被挤走。在我们的做法里，清单每一轮都摆在它眼前，还有没完成的项，就不让它交最终答案。

【4 它们怎么帮 Agent】 [图 D4：开工前、施工中、收工时]
放到时间线上：开工前，计划模式管方向，你先确认。施工中，任务清单帮它少漏步，少跑偏，但不是保证。收工时，每一项要有能检查的标准，通过，或者不通过。注意，模型没有变聪明，变的是：有了一张摆在外面的纸，你也看得见。另外要说，计划模式的价值，我们这次没测，它主要是让你，在改之前，看一眼。

【5 Claude Code 里的样子】 [引用卡：官方文档页面，待做]
Claude Code 里都有。计划模式：按 Shift 加 Tab，读文件，写计划，批准之后才开始改。任务清单：按 Ctrl 加 T 显示，压缩之后也不丢。官方没有写任务的字段，所以下面是我们自己设计的版本。

【6 我们自己做的】 [图 D5：两套工具；图 D6：清单每轮显示]
计划模式很小：只给读文件和搜索，加一个提交计划的工具，写文件的工具根本不给，你批准，才打开。清单也只有一个工具，叫写清单，每次传整份，同一时间只有一项进行中。注意，Claude Code 现在用的是创建和更新两个任务工具，我们这个，是更简单的老形状。

【7 真实测试】 [图 D7：结果图]
这只是我们自己的小测试。仓库有四个插件，九个 skill，四个子 Agent，我们故意放进十二处错误，让它按规则检查，全部修好。三种设置，各跑五次：什么都不加，加清单，计划加清单。什么都不加：六十处，改对五十九处，平均十五轮。清单：六十处全对，平均三十轮。计划加清单：全对，平均二十七轮。唯一漏掉的一次，在什么都不加里：漏了一个链接，却说全部符合。这是一次，不是规律。每种设置只跑了五次，只有一次出错，所以不能说清单更准。能说的是：轮数，大约翻了一倍。另外两个更小的任务，也全部做对。

【8 两个真实的坑】 [琥珀色“坑”卡]
第一个：我们第一版，把读文件也拦了，计划只能盲写。第二个：第一版里，计划写太长被截断，五次有两次，一个文件都没改。现在被截断的回复会丢掉，让它写短一点。所以，清单每一项，要能检查，别写“修好所有问题”。

【9 合起来】
一，计划模式，是给你的：改之前先看一眼。二，清单，让你看到进度，Agent 也可能不容易漏步。三，它们要花轮数，大约两倍，短任务不一定需要。四，每一项，要有能检查的标准。
