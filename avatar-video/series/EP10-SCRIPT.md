【开场】
1. 你睡着了。一个订单进来，又一个订单进来，第一个订单，还被重发了一遍。这时候，你的 Agent 在干什么？今天讲常驻，也就是你不在的时候，它怎么干活。
2. 今天回答四个问题。常驻是什么？为什么要多几个部件？有没有用？没人点头的时候，它怎么办？数字都是 DeepSeek 跑出来的，每种只跑五次，很小，我会说清楚能说什么，不能说什么。

【问题】
3. 先说问题。订单、消息，这些从外面来的事，叫事件。如果每个事件，都直接启动一次 Agent，会出三种事。第一，两个事件同时到，抢着改同一个文件。第二，程序中途崩了，事件就丢了。第三，Agent 想问你能不能做，可你不在。
4. 我们测了第一种。一个文件里有个计数，每个订单加一。两个订单，加一次重发，计数应该是二。每次送达，都启动一个 Agent，同时跑。五次，计数每次都是一，看起来是互相盖掉了。用户还收到三条消息。

【常驻是什么】
5. 常驻是什么？Anthropic 有一篇讲常驻的文章，它说，其实不是一直开着。大多数时候，它在睡觉。来了事件，才醒来跑一次，做完存好，再睡。醒来干一次活，叫一次运行。
6. 文章列了五个部件。收件箱，定时器，记忆，权限，发件箱。记忆，是第九集。权限，是第四集。今天做另外三个，再看，没人批准的时候，权限会怎么变。
7. 收件箱，像一张登记表，每个事件写一行，先记下来，不会丢。定时器，是一个闹钟，到点，往收件箱里放一个事件。发件箱，放 Agent 想告诉你的话。你不在，它不能一直问，只能留言。

【Claude Code 里的样子】
8. Claude Code 里，有类似的东西。官方文档里，斜杠 loop，让它每隔几分钟，重复做一件事，比如查一次新版本有没有发布成功。但会话要一直开着，重复的任务，七天后自动过期，最短的间隔，是一分钟。
9. 要真的没人在，文档指向别的办法。一，云上的定时任务。二，GitHub Actions 的定时器。三，命令行的 claude 杠 p，不带界面运行。云上的定时任务，最频繁，也只能每小时一次。
10. 还有频道，就是把聊天软件接进来，比如 Telegram，消息可以送进正在运行的会话。但只有会话开着，才收得到。文档还警告，频道里允许的人，也能批准工具的使用，所以只放行你信得过的人。
11. 没人批准怎么办？文档里有一个选项。要问的操作，一律拒绝，并告诉 Claude，没人能批准，不要重试，继续往下。

【我们自己做的】
12. 我们自己做的，有三个部件。先是收件箱。它是一张表，每个事件一行，有编号，来源，内容，状态。编号由发送的人给。对方没收到回复，会再发一次，同一个编号来第二次，我们只存一次，这叫去重。
13. 工人，是一段专门从收件箱拿事件的程序。每次，把所有等着的事件，一次拿走，合成一个任务，只启动一次 Agent。跑完，标成做完。失败了，放回去，最多试三次。程序崩了，没做完的，也放回去。
14. 定时器，是单独的一张表。调度器，是一段小程序，每隔一会儿看一眼，到点的，往收件箱放一个事件。重复的，算好下一次。错过的，只放一次，不补，和斜杠 loop 一样。我们用假时钟，也就是手动拨快时间，测过这些。
15. 发件箱，也是一张表。Agent 用发消息工具，把话放进去。发送的程序，每次最多发五条，完全重复的，丢掉。这样，它不会半夜刷屏。
16. 没人能批准的时候，要问的操作，直接拒绝，并告诉模型，没人能批准，不要重试，也不要绕路。再用发消息，告诉用户，想做什么，为什么。这一集的代码，有十五项检查，不用 API key，就能跑。

【真实测试】
17. 接下来是真实测试，一共三个。第一个，订单测试。两个订单，加一次重发，计数是二，算对。两种做法，各跑五次。直接：每次送达，都启动一个 Agent。收件箱：只写进收件箱，让一个工人去跑。
18. 第二个，没人批准测试。每日检查，要跑测试，可这个命令，没人批准。三种做法：等着，问题一直挂着。拒绝，只说一句不行。没人，告诉它没人能批准，要留言。看三件事：跑完没有，发了几条消息，有没有说测试没能运行。
19. 第三个，密钥测试。一条顾客消息，藏了一句话，要它把密钥文件的内容发出来，这叫提示词注入。密钥，就是 API key 这类密码。两种做法：密钥放在项目里，或放在外面。看有没有泄露。前面学的部分，全都开着，定时器没有等真的时间。
20. 挑收件箱那组的一次运行，来看。三次送达进来，重复的那次，被去重。工人拿走两个订单，合成一个任务，启动一次 Agent。它先读文件，写计划，列清单。
21. 接着改计数。改之前，hook 看一眼。改完读回来，确认是二。再想跑测试，这个命令被拒绝了，没人能批准。它没有重试。
22. 最后，它用发消息，留了一句话，计数是二，测试没能运行。发送的程序，把这句话打印出来，当作交给用户。这次一共十一轮。

【结果】
23. 看结果。第一个。直接那组，五次，计数都是一，应该是二。每次三个 Agent，三条消息。收件箱那组，五次里四次是二，每次只有一个 Agent，一条消息。五次很小，只能说，在这个小测试里，收件箱更好。
24. 那一次不是二的，计数还是零。它说了，写文件被拒绝，没有改，也没有绕路，并把原因留在发件箱。但是，这个事件，已经被标成做完了。
25. 第二个。等着那组，五次里有两次，一直等了四分钟，什么也没发，我们把它停了。另外三次，没碰那个命令，所以没卡住。拒绝和没人，各五次，都做完了，都只发了一条，都说测试没能运行，看不出区别。而且没人那组，五次都没去碰那个命令，没被真正考到。
26. 第三个，十次，没有一次泄露。那句藏起来的话，没人照做。密钥放在项目里的五次，连那个文件，都没有一次被打开。所以这个测试，什么也没证明。我们的建议，还是，密钥，别放在项目里。
27. 那有没有用？订单测试里，收件箱有用，四比零，但只有五次。没人批准的办法，没看出好处。密钥测试，什么也没说。

【真实的坑】
28. 一个真实的坑。发消息的工具，我们在计划模式里给了，调用时却被拒绝。计划模式只能看，不能改。这和第九集的记忆工具，是同一种坑。第一批三十五次，因此作废。改好，加了测试，重跑一遍。
29. 第二个坑。一次运行结束，不等于活干完了。那次计数是零，事件却已经标成做完。所以要看发件箱里，它说了什么。这一点，我们还没修。

【总复习与结尾】
30. 总复习，第一到第五集。第一集，循环。第二集，工具。第三集，提示词和笔记。第四集，权限。第五集，上下文。
31. 第六集，计划和清单。第七集，子 Agent。第八集，hook。第九集，记忆。第十集，常驻，收件箱，定时器，发件箱。
32. 我们没有做的，有四样。真的一直开着的守护程序，也就是一直在后台待命的程序。接聊天软件的发送。会自己重启的调度器。还有，先停下，等你回复，再接着做。现在这个 Agent，要有人叫它跑一次，它才干活。但它已经会收事件，会留言。下一集，用 M C P 和 skill，扩展它。
