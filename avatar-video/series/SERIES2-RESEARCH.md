## Facts by theme (paraphrase; short quotes only)
- Managed settings and precedence (settings): scopes user, shared project, project local, managed. Highest first: managed, command line, project local, shared project, user. "Nothing in your own settings files or `--settings` overrides a managed key." Lists such as `permissions.allow` merge across files. A repository's `permissions.allow` and most `env` wait for folder trust; `deny` and `ask` apply at once; `defaultMode` auto and bypassPermissions are ignored from project files; telemetry variables in a repo are ignored. A managed file on a device does not reach cloud sessions, only server-managed settings do.
- Permissions: evaluated "deny, then ask, then allow"; an allow cannot carve an exception out of a deny. "Permission rules are enforced by Claude Code, not by the model." `allowManagedPermissionRulesOnly`, `disableBypassPermissionsMode`, `disableAutoMode`, `denyInsteadOfPrompting` (for unattended runs). Managed denies cannot be overridden even by `--allowedTools`. "Bash permission patterns that try to constrain command arguments are fragile" (real enforcement needs sandboxing). Read/Edit deny rules do not cover subprocesses. Bypass mode: "Only use this mode in isolated environments."
- Authentication (iam page): `forceLoginMethod` and `forceLoginOrgUUID` in managed settings; `allowedProviders` limits which services a machine may reach (v2.1.285+). Credential precedence: a leftover API key can silently override a subscription. Credentials in the macOS Keychain, a 0600 file on Linux.
- Monitoring (OpenTelemetry): configure through the managed `env` block; a repo cannot set exporter variables; developer-set endpoints are removed when managed settings set the endpoint. Content (prompts, assistant responses, tool details, tool content, raw API bodies) is OFF by default, each with its own variable. 8 metrics (session.count, lines_of_code.count, pull_request.count, commit.count, cost.usage, token.usage, code_edit_tool.decision, active_time.total) and about 28 events (e.g. user_prompt, tool_result, tool_decision, api_request, api_error, permission_mode_changed, hook_execution_*, compaction, subagent_completed, managed_settings_resolved); spans interaction, llm_request, tool, tool.blocked_on_user, tool.execution, hook.
- Costs: Teams/Enterprise seat allowance with 5-hour and weekly windows, overflow as usage credits with spend limits at org, group or member level; Console workspace spend limits; on cloud providers budgets live in the provider console. A benchmark of about $13 per developer per active day (the page's figure). `modelPricing` managed setting makes reported cost match contract pricing. Background work spends tokens while idle. The page documents no standalone "team cost control" setting.
- Data usage: no training on commercial-plan prompts by default; commercial retention 30 days; zero data retention only for qualified Enterprise accounts ("ZDR is not included in the standard Enterprise plan"); local transcripts plaintext in ~/.claude/projects for 30 days (`cleanupPeriodDays`); WebFetch sends the hostname to api.anthropic.com unless `skipWebFetchPreflight`.
- Dev container: pin the version with npm and `DISABLE_AUTOUPDATER`; do not mount ~/.ssh or cloud credentials; a managed-settings file copied into /etc/claude-code/ can be removed by anyone with write access, so use server-managed settings or MDM for policy that cannot be bypassed; `disableBypassPermissionsMode` blocks the bypass flag everywhere.
- Secure deployment (Agent SDK): threat model prompt injection and model error, defense in depth; isolation options sandbox runtime, hardened Docker (`--cap-drop ALL`, read-only, no network, non-root), gVisor, Firecracker; run a proxy outside the boundary that injects credentials; "Within your proxy's allowlist, the agent can send data to any allowed domain."
- Hosting (Agent SDK): one CLI subprocess per session; local disk is lost on restart so persistence needs a session store; start at 1 GiB RAM, 5 GiB disk, 1 CPU per agent; multi-tenant isolation = empty setting sources, auto memory off, per-tenant config dir, working dir and egress rules; limits listed: no top-level session timeout, memory growth, subagent fan-out rate limits.
- Gateway and providers: a gateway gives server-side provider credentials, per-developer tracking, budgets, audit logging; Anthropic "doesn't endorse, maintain, or audit" third-party gateways; lock down with `allowedProviders` plus a base URL in managed `env`; pin model versions with the ANTHROPIC_DEFAULT_*_MODEL variables; CMEK does not cover operational telemetry.
