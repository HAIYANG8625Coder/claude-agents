# Episode 2 script v2 (spoken Chinese, landscape; reviewed; demo narration follows ep02/demo/run-fix.txt and run-recover.txt)

【0 开场】
在我们这个程序里，模型自己，什么都不会执行。它能读文件，改代码，全靠我们给它的工具。今天，我们给上一集的循环，装上四个真正的工具：读文件，搜索，改文件，执行命令。再看它怎么自己修好一个错误。第二集，只讲一件事：工具是什么，怎么设计，才不会让模型迷路。

【1 回顾】
上一集的循环是这样的：调用模型，模型提出工具请求，我们的代码去执行，再把结果还给模型。所以，工具有多好，Agent 就有多强。

【2 一个工具是什么】
一个工具，由四样东西组成：名字，说明，参数的格式，还有真正执行的函数。注意，模型看不到你的函数，它只能看到前三样。它靠名字和说明，决定什么时候用。靠参数的格式，决定怎么填。Anthropic 的 A P I 文档建议，说明至少写三四句话。要讲清楚四件事：这个工具做什么，什么时候用，参数是什么意思，有什么要注意的。我们这一集的说明，为了屏幕放得下，写得短一些。Anthropic 的工程文章也说，写工具说明，要像给一个新来的同事，写交接文档。

【3 四个工具】
这一集，我们做四个：read file，grep，run bash，和 edit file。

第一个，read file。它读一个文本文件，把每一行加上行号返回。行号很有用，模型可以直接说，第三行有问题。

第二个，grep。在一个文件夹里，用正则表达式搜索，返回文件名，行号，和那一行的内容。最多返回五十条。

第三个，run bash。在项目文件夹里执行一条命令，返回输出和退出码。我们设了二十秒的超时。注意，这个工具真的会执行命令，所以只在一个可以随便弄坏的文件夹里试。权限，是后面要讲的内容。

第四个，edit file，也是最有意思的一个。它不是重写整个文件，而是把文件里的一段文字，精确地替换成另一段。它有三个参数：路径，旧文字，和新文字。要求是，旧文字必须一模一样，而且只出现一次。

【4 为什么这样改文件】
为什么不让模型重写整个文件？因为重写，要输出整个文件，又慢又贵，还容易把没动的地方改坏。精确替换，只需要说清楚，改哪一段。Claude Code 的 Edit 工具也是这样。官方文档说，它做的是精确字符串替换，不用正则，也不模糊匹配。旧文字必须只出现一次，除非明确要求全部替换。而且有些模型，要求先读过这个文件。我们的版本，也加了两条规则：没读过，不让改。出现零次或者多次，也不让改，并且告诉模型，到底出现了几次。

【5 错误也是结果】
这就带来第一条设计原则：出错的时候，别让程序崩溃。把错误写成清楚的话，还给模型。Anthropic 的文章说，错误信息要告诉模型，具体怎么改进，而不是丢给它一串错误代码。A P I 里，tool result 还有一个字段，叫 is error，设成真，就是告诉模型，这次执行出错了。比如，模型没读文件就想改，我们返回：先读文件。它一般就会自己先去读，再来改。

【6 别塞满上下文】
第二条原则：返回的内容，别太长。一个几万行的文件，或者一条输出巨大的命令，会把上下文塞满。所以，读文件和命令的输出，超过四千个字符，我们就砍掉，并且告诉模型：请求少一点。我们这个提示很简单。Anthropic 的文章建议，截断的时候，要引导模型，换一个更窄的调用。Claude Code 自己也有限制。官方文档说，Bash 的输出，超过大约三万个字符，就会存到文件里，只留一段预览。Anthropic 的文章还说，Claude Code 默认把工具的返回，限制在两万五千个 token 以内。

【7 路径和超时】
第三条原则：守住边界。读文件，搜索，改文件，这三个工具，会检查路径是不是在项目文件夹里面，不在，就拒绝。命令有超时，二十秒还没结束，就停下来，告诉模型。但要注意，run bash 里的命令，不受这个路径检查管，它可以碰到别的文件夹。所以，真正的权限，我们后面再加。

【8 跑一遍】
来跑一遍，这次演示用的是 DeepSeek 的模型。我们在一个小项目里，放了一个故意写错的函数：add，本来应该相加，却写成了相减。任务是：这个文件夹里的测试失败了，找出原因，修好它。第一轮，模型先执行 L S，看看文件夹里有什么。第二轮，它一次提出两个请求：读 calc 文件，读测试文件。这就是上一集说的，一条回复里，可以有好几个请求。读完以后，第三轮，它直接改文件，把相减换成相加。第四轮，运行测试，确认通过。第五轮，它没有再要工具，循环结束。最后它的回答是：问题出在 add 函数，写成了相减，现在已经改成相加，测试全部通过。

【9 错误恢复】
再看一个。这次，我在任务里，要求它不读文件，直接改。第一轮，它调用 edit file，我们返回错误：先读文件。第二轮，它去读文件。第三轮，再改，这次成功了。最后它说，已经改好了。没有崩溃，也不需要人介入。错误本身，就是指引。

【10 对比 Claude Code】
和 Claude Code 比，我们差在哪里？我们的四个工具，对应它的 Read，Grep，Bash，和 Edit。它还有 Write，Glob，抓取网页，搜索网页，子 Agent 等更多工具。官方文档还说，在 mac O S 和 Linux 上，Grep 和 Glob 默认没有开启。Claude 会通过 Bash，去用系统自带的 grep 和 find。另外，默认情况下，读文件不需要询问。改文件，和执行命令，都要先问你。这一点，后面会专门讲。

【11 三个坑】
最后，说三个设计工具时容易踩的坑。第一，工具太多，而且功能重叠，模型就容易选错。Anthropic 的文章建议，少而精，把相近的功能合并。第二，说明太含糊，模型不知道什么时候该用它。第三，参数名含糊。比如，叫 user，还是叫 user id，模型会理解成不同的东西，名字要写清楚。

【12 总结】
这一集，记住四件事。一，工具的说明，是写给模型看的。二，改文件，用精确替换，只改一处。三，出错，要把错误写成清楚的话，还给模型。四，返回的内容，别太长，命令要有超时。下一集，我们给它一份系统提示，和一个笔记文件，让它更懂你的项目。你写过的工具里，哪一个，最容易被模型用错？评论区告诉我。
