# Episode 6 script v1 (spoken Chinese, landscape; numbers from ep06/demo/*.json in the agent-from-scratch repo; all runs are our own DeepSeek runs; docs facts from EP6-RESEARCH.md)

【0 开场】
同一个任务，同一个模型。不给任务清单，十二处错误，五次里改对了五十九处。给清单，六十处，全对。但是，清单让它多跑了一倍的轮数。下面所有的数字，都是我们用 DeepSeek，真实跑出来的。任务是一件我们每天都在做的事：提交代码之前，检查整个仓库，符不符合规则，不符合的，就改掉。今天第六集，讲两个工具：计划模式，和任务清单。

【1 为什么长任务会出事】
长任务，最怕两件事：做到一半忘了一步，或者，还没做完，就说做完了。Anthropic 讲长任务的工程文章，把这叫做，过早宣布胜利。他们的办法，是一份功能清单，每一项，都标着过没过。我们今天的两个工具，思路一样：把计划，从模型的脑子里，拿到纸面上。

【2 Claude Code 的计划模式】
先看 Claude Code。按 Shift 加 Tab，切换到计划模式，也可以在一句话前面，加斜杠 plan。官方权限模式页面说：Claude 会读文件，会探索，会写计划，但是不会改你的源码。直到你批准计划，编辑才会解锁。计划好了，它会给你三个选项：批准并自动接受编辑，批准但是逐个审核编辑，或者，不批准，继续计划。按 Ctrl 加 G，还可以在编辑器里，直接改这份计划。

【3 我们的计划模式】
我们的做法很小。计划模式下，模型只拿到读文件，和搜索，再加一个新工具，叫 submit_plan。写文件的工具，根本不给；万一它硬要调用，就返回一句：计划模式下不能用。模型交上计划，我们展示给你，你可以直接批准，也可以写一句意见，让它重写。批准以后，计划模式关闭，编辑工具才出现。

【4 Claude Code 的任务清单】
再看任务清单。官方交互模式页面说，任务清单，是 Claude 的待办清单：它为多步骤的工作，建立的条目，每一项的状态，是待做，进行中，或者完成。按 Ctrl 加 T，显示或者隐藏，一次最多显示五项。官方工具页面，列了四个工具：创建，读取，列出，更新。清单在压缩之后，也不会丢。注意，官方没有写，任务的字段，和状态的名字，所以后面这个版本，是我们自己设计的。

【5 我们的 todo_write】
我们只做一个工具：todo_write。每次，把整份清单传进去。每一项，有任务，和状态。规则写在提示里：先把所有步骤，列成待做；每次只有一项，在进行中；检查过，才能标完成；还有没完成的项，就不要交最终答案。工具会检查：同时两项进行中，就报错。然后把清单，原样显示给它看。

【6 真实测试】
来真的跑。仓库有四个插件，九个 skill，四个子 Agent。我们故意放进去十二处错误：缺的链接，坏的链接，名字对不上的清单文件，缺的版本，README 少了几行，还有一个 skill，放错了地方。任务只有一句：提交之前，按 CLAUDE 点 M D 的规则检查，全部修好，再用表格告诉我。三种设置，各跑五次：什么都不加，加任务清单，计划模式加清单。看屏幕：什么都不加，五十九处改对，平均十五轮；任务清单，六十处全对，平均三十轮；计划加清单，六十处全对，平均二十七轮。唯一的一次漏掉，在什么都不加里：它漏了一个链接，最后却写，所有规则都符合了。五次里一次，样本太小，不能说清单更准。我们还跑了两个更小的任务，八件事，和十六件事，三种设置，全部做对，清单只是让轮数翻倍。

【7 两个真实的坑】
这次，我们真的踩到了两个坑。第一个：我们的第一版计划模式，把读文件也拦了。模型只能盲写计划，计划里写着，我还没看过任何文件。修好以后才对。第二个：计划写得太长，超过了单次输出的上限，被截断。修好之前，五次里有两次，因为这个，一个文件都没改，零分。现在，被截断的回复会丢掉，再让它写短一点。还有一条，来自官方的最佳实践页面：要给 Claude 一个能跑的检查，通过，或者不通过。所以清单里的每一项，都要能检查，别写修好所有问题这种，没法验证的大任务。

【8 合起来】
四件事。一，计划模式，是给你的：改之前，你先看一眼。二，任务清单，也主要是给你的：你能看到进度。三，它们要花轮数：我们测到，大约两倍，所以短任务，不一定需要。官方也写，新一点的模型，不写清单，也能追踪多步骤的工作。四，每一项，要有一个能检查的标准。下一集：子 Agent。

【9 结尾】
