# Episode 1 script v2 (spoken Chinese, vertical; reviewed; section 6 to be re-checked against the real run)

【0 开场】
Claude Code 为什么能自己读文件，自己做事？因为它背后，有一个循环。今天，我用大约五十行 Python，把这个循环写出来。这是新系列的第一集：从零做一个，Claude Code 那样的 Agent。第一集，只讲一件事：Agent 的核心，就是一个循环。

【1 准备】
先说你需要准备什么。一台能运行 Python 的电脑，一个终端，还有一个大模型的 API 密钥。我们的代码，按 Anthropic 的消息格式来写，所以 Claude 的 API 和 DeepSeek 的 API，都能跑，只要改一个环境变量。这个系列，我先用 DeepSeek 的模型来演示，因为价格很低。注意，Claude 的 Pro 订阅，不包含 API。想用 Claude 的话，密钥要在开发者控制台，单独创建，单独付费。

【2 Agent 是什么】
什么是 Agent？Anthropic 在工程文章里的说法是：Agent，通常就是大模型，在一个循环里，根据环境的反馈，使用工具。三个关键词：大模型，工具，循环。聊天机器人，你问一句，它答一句，就结束了。Agent 不一样。它会自己决定，要不要先查点东西，看完结果，再决定下一步。打个比方，它像一个新来的实习生：你给他一个任务，他先看资料，做一步，看结果，一直做到完成。

【3 Claude Code 的循环】
Claude Code 的官方文档，把它的工作过程，分成三步：收集上下文，采取行动，验证结果。这三步会混在一起，反复进行。比如修一个错误：先读文件，是收集上下文。再改代码，是采取行动。再运行测试，是验证结果。那什么时候停？Agent SDK 的文档写得很清楚：模型的回复里，没有工具调用，循环就结束。文档还说，SDK 跑的，就是驱动 Claude Code 的，同一个循环。所以，我们今天做的，是同一个思路的，最小版本。

【4 一轮发生了什么】
来看一轮里，到底发生了什么。第一步，我们把用户的问题，发给模型。第二步，模型不直接回答。它回一条消息，里面有一块，叫 tool use，意思是：请帮我调用这个工具，参数是这些。注意，在我们这个程序里，模型自己，什么都没有执行，它只是提出请求。第三步，我们的代码，真的去执行这个工具，拿到结果。第四步，我们把结果，包成 tool result，再发回去。模型看到结果，再决定：继续用工具，还是直接回答。这就是一轮。为什么结果放在 user 消息里？因为在这套接口里，对话只有两个角色，user 和 assistant。工具的结果，是我们这一边发回去的，所以算 user 这一边。

tool use 这一块，里面有三个字段。id，是这次请求的编号。name，是工具的名字。input，是参数。我们回的 tool result，必须带上同一个编号，模型才知道，结果对应哪一次请求。有时候，模型一条回复里，会提出好几个请求。这时，我们要全部执行。再把所有结果，放进同一条消息里，一起发回去。

还有一个容易被忽略的事实：模型自己没有记忆。每一次调用，我们都要把完整的 messages 列表，重新发给它。所以，对话越长，每一轮发出去的内容越多，花的钱也越多。这个问题，后面我们会解决。

【5 写代码】
现在写代码，其实只有四件事。第一，准备一个 messages 列表，先放进用户的问题。第二，调用模型，把模型的回复，原样加进 messages。第三，看 stop reason。如果它不是 tool use，循环就结束，把回答返回。第四，如果是，就逐个执行它要的工具。把每个结果，包成 tool result，放进一条 user 消息，加进 messages。然后，回到第二步。整个循环，就这么多。stop reason 常见的值有三个。end turn，是模型自己说完了。tool use，是它想用工具。max tokens，是回答太长，被截断了。我们的代码，只判断是不是 tool use。代码里还有一句系统提示，告诉模型它的角色，我们先写得很简单。

我们只准备一个工具，叫 list files，列出一个文件夹里的文件。工具由三部分组成：名字，说明，和参数的格式。模型就是读这段说明，来决定，什么时候该用它。所以说明要写清楚。工具出错的时候，别让程序崩溃。把错误当成结果返回，模型读到错误，通常能换个办法。最后，加一个保险：最多跑十轮。

【6 跑一遍】
来跑一遍。问它：这个文件夹里有什么？第一轮，stop reason 是 tool use，模型要调用 list files。我们执行，把文件名返回。第二轮，模型拿到文件名，一般就会直接回答，stop reason 变成 end turn，循环结束。代码会把每一轮的 stop reason，和工具调用，都打印出来。看清楚每一步，是理解 Agent，最有用的习惯。我们再故意问一个不存在的文件夹。工具会返回一条错误。错误，也是结果的一种，模型读到之后，会据此回答你，或者换一个路径再试。如果是前面那个两轮的例子，跑完以后，messages 里一共有四条。第一条，user，是我们的问题。第二条，assistant，里面是 tool use。第三条，user，里面是 tool result，也就是文件名。第四条，assistant，是最后的回答。这四条，就是这次任务的完整记录。

【7 什么时候停】
什么时候停？两种常见情况。一种是正常结束：模型的回复里，没有工具调用。另一种是被我们强行停下：轮数到了上限。Agent SDK 里，也有这个选项，叫 max turns。默认是不限制。超过了，会返回一个 error max turns 的结果。Claude Code 里的子 Agent，也可以设置这个上限。所以自己写的时候，一定要加这个保险。不然模型一直调用工具，程序就停不下来，钱也一直在花。

【8 三个坑】
最后说三个，容易踩的坑。第一，tool result 没发对。编号对不上，或者漏了一个，API 通常会直接报错。第二，没有轮数上限，程序一直跑，一直花钱。第三，以为模型自己执行了代码。其实，这里执行的，是你的程序。所以，什么能做，什么不能做，也该由你的程序来决定。这正是后面，权限要讲的事。

【9 我们缺什么】
回头看，我们做的，和 Claude Code 还差很多。它有读文件，改文件，执行命令这些工具。有权限，危险的操作，要先问你。上下文快满的时候，会自动压缩。还能把任务，交给子 Agent。这些，后面我们一个一个加。这一集，讲了四样东西：messages 列表，工具，stop reason，和轮数上限。记住一句话：Agent 的核心，是一个循环。调用模型，执行工具，把结果还给它，直到它不再要工具。下一集，我们给它加上，真正有用的工具。你最想先看，哪一块？评论区告诉我。
