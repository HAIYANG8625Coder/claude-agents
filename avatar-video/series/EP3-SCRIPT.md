# Episode 3 script v2 (reviewed, 15 fixes applied) (spoken Chinese, landscape; demo narration follows ep03/demo/run-no-notes.txt, run-with-notes.txt, evals.txt)

【0 开场】
同一个 Agent，同一个模型，同一个任务。只多了一份笔记，它的做法就变了。这一集，我们给上一集的 Agent，加上系统提示，和一个笔记文件。再用固定的任务，检查它有没有变好。第三集，只讲一件事：不重新训练模型，怎么引导它。

【1 回顾】
上一集，我们给循环装上了四个工具。但是，它现在对我们的项目，一无所知。每次都要从头摸索。这就是系统提示，和笔记文件，要解决的问题。

【2 系统提示是什么】
系统提示，是 A P I 里一个单独的参数，叫 system，和 messages 分开。每次调用，都要带上它。Anthropic 的文档说，给系统提示设定一个角色。这能让 Claude 的行为和语气，更聚焦你的场景。我们给它三部分：一句角色，几条规则，还有环境信息。角色是，你是一个在项目文件夹里工作的小型编程助手。规则是，先看再做，改文件前先读，改完要跑测试，回答要简短。环境是，项目文件夹的路径，和操作系统。

【3 笔记文件】
但是，项目的约定，不适合写在系统提示里。每个项目不一样。所以，Claude Code 用的是笔记文件，叫 CLAUDE 点 md。官方文档里，它有几个位置。你自己的用户目录下，那个 点 claude 文件夹里，一份，对所有项目生效。项目文件夹里，一份，可以和团队共享。还有一份 CLAUDE 点 local 点 md，放你个人的偏好，不提交到仓库。另外，还有组织统一管理的那一份。Claude Code 会从你的工作目录，一直往上，每一层都加载。子文件夹里的笔记，要等到 Claude 读写那个文件夹里的文件，才会加载。几份笔记，是拼在一起的，不是互相覆盖。

【4 笔记放在哪】
这里有个很重要的细节。官方文档说得很明确。CLAUDE 点 md 的内容，是系统提示之后的一条用户消息。它不是系统提示本身。文档还说，Claude 把它当作背景信息，不是强制执行的配置。我们的版本，也这样做。程序启动时，读项目文件夹里的 NOTES 点 md，放进第一条用户消息，后面接着任务。没有笔记文件，就只发任务。我们还加了一个开关，show prompt，把模型实际收到的内容，原样打印出来。出了问题，先看这个。

【5 笔记写什么】
笔记里写什么？官方文档给了几条建议。第一，短。目标是每个文件，少于两百行，太长，遵循度会下降。我们的版本，超过两百行，会打印一个警告。第二，只写模型从代码里看不出来的东西。能一读代码就知道的，别写。第三，具体，能检查。文档的例子是，写，提交前运行 N P M test，比写，测试你的改动，更好。第四，什么时候加一条？当 Claude 第二次犯同样的错误。Claude Code 里，还有一个斜杠 init 命令，可以自动生成第一版。

【6 一份笔记】
我们的笔记，一共五条。钱用整数分，不用浮点数。百分比折扣要四舍五入。比如，一千零五分，打五折，是五百零二点五，进成五百零三分。每个函数，写一行说明。新的辅助代码，放进 helpers 文件夹，一个函数一个文件，文件名就是函数名。最后一条，回答的最后，写一行，以 Done 冒号开头，说明改了什么。

【7 怎么知道有用】
有没有用，不能靠感觉。我们做了一个很小的测试集。两个固定任务。每个任务，有笔记，和没有笔记，各跑三次。检查，是代码做的，不是让模型自己说。比如，导入模块，调用函数，看结果对不对，看文件在不在。这次只用了一个模型，DeepSeek 的，样本很小，只是演示这个方法。结果是这样：折扣任务，没有笔记，四舍五入对了两次，有笔记，三次都对。整数结果和一行说明，没有笔记，也是三次都对。四舍五入，只差一次，可能是运气。折扣任务里，最后一行 Done，没有笔记，零次，有笔记，三次。辅助函数任务，没有笔记，放进 helpers 文件夹，零次，有笔记，三次，而且函数都能用。

【8 跑一遍】
再来看其中一次真实的运行。任务是：加一个辅助函数，把价格，向下取整到五分的倍数。没有笔记，模型直接把它，写进了 pricing 文件，没有说明，也没有 Done 那一行。有笔记，模型一开始，就带着那份笔记。它新建了 helpers 文件夹，文件叫 round 下划线 down 下划线 5 点 py，里面有一行说明，也跑了原来的检查，最后一行，以 Done 开头。同样的模型，同样的任务，差别，只有那份笔记。

【9 一个意外】
测试，也会出意外。第一次跑，有两件事不对。一是，输出长度的上限，设小了，有一次回答被截断。我们改大了。二是，更有意思，折扣任务里，模型把四舍五入的小函数，也放进了 helpers 文件夹，因为笔记说，新的辅助代码，放这里。这条规则，我写得太宽。而我的检查代码，没有考虑这种写法，报了错。有问题的，是检查代码，不是模型。教训是，检查代码本身，也要测。还有，一条规则，可能影响到别的任务。

【10 对比 Claude Code】
和 Claude Code 比，我们差在哪里？它的笔记，有多个层级，可以用 at 符号，引入别的文件，最多嵌套四层。更多功能，后面再讲。官方文档还提醒：必须每次都发生的事，不要只写在笔记里，要用钩子，也就是 hooks。因为笔记是引导，不是强制。

【11 三个坑】
最后，三个坑。第一，笔记越写越长。文档说，太长会占更多上下文，模型就遵循得更差。第二，规则写得模糊，或者模型没法检查，比如，写好代码。要写成，能验证的。第三，改了提示，没有重新测试。这一集的测试集，就是为这个准备的。

【12 总结】
这一集，记住四件事。一，系统提示，写角色，规则，和环境。二，项目的约定，放进笔记文件，作为第一条用户消息。三，笔记要短，要具体，只写代码里看不出来的。四，改了提示，就用固定的任务，重新测一遍。下一集，我们要给它一道关卡：权限。让它做事，又不会乱来。你的笔记文件里，最有用的一条规则，是什么？评论区告诉我。
