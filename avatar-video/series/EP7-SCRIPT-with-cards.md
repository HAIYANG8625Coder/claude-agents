【0 开场】 [封面卡]
  🖼 封面卡：标题「Agent 的小助手：子 Agent」，副标题「让它去翻几十个文件，只带回一页纸」，右下角「从零做 Agent · 第 7 集」
  🖼 一张上下文窗口示意：文件一个个往里掉，窗口越来越满
Agent 读一个文件，对话就长一截。读了好多个，后面的活，都得背着它们。让它把本周的帖子，整理成一张表，就是这样。今天讲：子 Agent。它是什么，为什么需要，再用我们自己的真实任务，测一测。

【1 问题出在哪】 [图 D1：上下文被工具结果塞满]
  🖼 图 D1 分 3 步出现：①对话条里只有任务；②读文件的结果一块块堆进来；③一行字「只想要一个答案，却背着 N 个文件」
  🖼 小标注：上下文 = 模型能看到的这场对话（第 5 集）
先回忆第五集：模型能看到的，只有这一场对话，叫上下文。每次读文件，结果都留在里面。你只想要一个答案，可它已经读进来好多个文件。后面的活，都要带着它们。

【2 什么是子 Agent】 [图 D2：主 Agent 和子 Agent]
  🖼 图 D2：左边主 Agent 的长对话，右边派出一个子 Agent（自己的新对话，小窗口），箭头回来只带一张「一页纸」
  🖼 类比小图：图书馆 · 翻书 · 一页纸
子 Agent，是主 Agent 派出去的小助手。它有自己全新的对话。干完一件小事，只把一句结论带回来。像派助手去图书馆：他翻了好多本书，你只收到一页纸。

【3 为什么需要，代价是什么】 [图 D3：好处和代价]
  🖼 图 D3 两栏：好处（主对话干净、只读更安全）/ 代价（多花词元、可能漏细节）
  🖼 数字条：Agent ≈ 4× 聊天；多 Agent 研究系统 ≈ 15×（来源：Anthropic）
  🖼 小标注：词元 = 模型读写的字数
好处：主对话保持干净。而且我们只给它读和搜，改不了东西，更安全。代价：多花词元，就是模型读写的字数。Anthropic 说，他们的数据里，Agent 大约是普通聊天的四倍。他们自己的多 Agent 研究系统，大约十五倍。还有一个风险：它带回来的一页纸，可能漏细节。所以不是每次都值得。

【4 Claude Code 里的样子】 [引用卡：官方文档页面，待做]
  🖼 引用卡：Claude Code 官方文档「子 Agent」页（标题 + 来源行）：自己的上下文窗口，只返回总结
  🖼 列表卡：内置 探索 / 计划 / 通用；自定义 = 一个 Markdown 文件
  🖼 对比小图：Anthropic 研究系统（并行）vs 我们（一个接一个）
Claude Code 里本来就有。子 Agent 有自己的上下文窗口，只把总结交回来。内置几种：探索，计划，通用。你也可以写一个 Markdown 文件，定义自己的。Anthropic 的研究系统，是一个主 Agent，带着好几个子 Agent 同时干活。我们这一版不同，是一个接一个，不并行。他们也说，任务要大家共享同一份上下文，就不太合适。

【5 我们自己做的】 [图 D4：代码路径；代码页]
  🖼 图 D4：主循环 → 委派工具 → 子 Agent（全新对话 · 只有读文件和搜索 · 轮数上限）→ 只回最终回答
  🖼 代码页：run_subagent 的核心几行，高亮「全新 messages」「只读工具」「轮数上限」「只返回最后一句」
  🖼 提示条：任务里要写清楚全部要求，它看不到主对话
我们只做最小的一版。一个委派工具。委派，就是把事交给别人。参数只有一段任务。子 Agent 从空白对话开始，只有读文件和搜索。它有轮数上限。最后只把最终回答，交回主 Agent。注意：它看不到主对话。所以任务里，要写清楚全部要求。

【6 真实测试】 [3 张介绍页：任务，评分，设置；再是结果图]
  🖼 介绍页 1「测什么」：从发帖记录里找出 11-13 到 11-19 的小红书笔记，共 21 条，抄下话题标签，做成表，存文件
  🖼 介绍页 2「怎么评分」：一行对（日期 + 平台 + 标题）/ 标签全对 / 模型调用次数（= 循环转几轮）
  🖼 介绍页 3「两种设置」：什么都靠自己 / 任务里明说用子 Agent；各 3 次，DeepSeek
先说测什么。从发帖记录里，找出十一月十三号到十九号，发的小红书笔记，一共二十一条。打开帖子文件，抄下话题标签，做成表，存成文件。再说怎么评分。一行的日期、平台、标题都对，算这一行对。标签要全对，才算标签对。我们看三个数：表格对了几行，标签全对几行，模型调用几次。一次模型调用，就是循环转一轮。最后是两种设置，各跑三次。一种什么都靠自己。一种在任务里明说，让子 Agent 去读文件。

【7 看每个部分在干什么】 [时间线：一次真实运行，每个部分带标签]
  🖼 时间线图：一次真实运行的横向时间轴，每个环节带一个彩色标签和「第 N 集」角标：系统提示+笔记（3）→ 读文件/搜索（2）→ 计划模式（6）→ 任务清单（6）→ 权限检查（4）→ 清旧结果/压缩（5）→ 子 Agent（7）；底部一条一直转的循环线（1）
  🖼 标注：计划批准和权限询问，在测试里由程序自动答应
这是其中一次真实运行，我们顺着看。出发时，它带着系统提示和笔记，第三集讲的，规矩和记忆。接着，它用读文件和搜索，第二集的工具，这是它的眼睛。第六集的计划模式：它先只看，交出计划，才动手。测试里，是程序替你点头。清单上，做完一项，划掉一项。要跑命令前，第四集的权限检查，先问一声。这里也是程序自动答应。读的文件多了，对话变长。第五集的上下文管理动手了：旧结果被清掉，太长，就压缩。这一集的子 Agent，在这里出场：把读文件，交给助手，只收回一句话。底下一直转的，是第一集的循环。每转一圈，就是一轮，一次模型调用。

【8 结果】 [图 D5：结果]
  🖼 结果图 D5：两组各 3 根柱，分别显示 表格对几行 / 标签对几行 / 模型调用次数；委派组下面标「子 Agent 出场：0 · 1 · 2 个」
  🖼 结论条：每组只有 3 次，不能说子 Agent 更好；主对话最多约 1.6 万词元
结果。先看什么都靠自己。表格全对的有两次，另一次对了二十行。标签全对的行数：二十一，二十一，二十。模型调用：三十四，四十，七十五次。再看让它委派。表格全对的也是两次，另一次二十行。标签全对的行数：二十一，二十，二十一。模型调用：二十六，二十八，三十三次。委派这组，模型调用少一些，三次都是。但要说清楚：第一次，子 Agent 根本没出场。第二次叫了一个，第三次叫了两个。每组只有三次，所以我不说，子 Agent 更好。能说的是：这个任务里，主对话最多涨到一万六千词元左右。主对话本来就不大，所以子 Agent 的好处，我们没有看出来。

【9 一个真实的坑】 [琥珀色“坑”卡；前后代码对比]
  🖼 琥珀色「坑」卡：压缩得太频繁（第一轮平均 35 次/次运行）
  🖼 前后代码对比页：旧版 vs 新版（多出 3000 词元才再压）；高亮差异那一行
  🖼 小注：同时把轮数上限从 60 提到 100，两处没有分开测
这次，我们真的踩到一个坑。第五集的上下文管理，压缩得太频繁。第一轮测试里，旧版平均每次运行，压缩三十五次。我们的判断是：系统提示、工具、笔记，这些固定部分，本身就接近触发线。压缩也压不掉。修复：压缩之后，等上下文又多出三千词元，才许再压。现在每次运行，不到四次。但要说清楚：我同时，把轮数上限，从六十提到一百。因为有一次，要跑七十五次。两处一起改的，没有分开测。所以不能说，全是修复的功劳。

【10 一到七集复习】 [图 D6：七集地图]
  🖼 图 D6：七集地图，一行七块：1 循环 · 2 工具 · 3 提示+笔记 · 4 权限 · 5 上下文 · 6 计划+清单 · 7 子 Agent，每块一句话，并标「刚才运行中出现的位置」
  🖼 最后一页：我们的 Agent 现在有的东西（一句总结）
回头看一遍。第一集，循环：看，做，再看。第二集，工具，是它的手和眼。第三集，系统提示和笔记，是它的规矩和记忆。第四集，权限，危险的事，先问你。第五集，上下文管理：旧结果清掉，太长压缩。第六集，计划模式和任务清单：先看，再做，少漏步。第七集，子 Agent：把一件杂活，交给助手，只收一页纸。刚才那次运行里，这几块都出现了。
