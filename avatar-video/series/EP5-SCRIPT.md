# Episode 5 script v2 (reviewed, 24 items applied or answered) (spoken Chinese, landscape; numbers from ep05/demo/repeat/*.csv and EP5-RESEARCH.md; all runs are our own DeepSeek runs)

【0 开场】
你的 Agent，读到第二十五个文件，窗口里已经装了两万五千个 token。我们让它，峰值只有一万三左右，答案也对。下面所有的数字，都是我们用 DeepSeek，真实跑出来的。任务是：二十四个文件，每个文件里，写着下一个文件的名字，沿着它读下去，找出里面的待办。为什么要管窗口？因为 Agent 每一轮，都要把整段历史，重新发一遍。Anthropic 的工程文章，把装得太满的后果，叫做 context rot：越满，效果越差。今天第五集，只讲一件事：上下文。

【1 窗口里装了什么】
窗口里，装了什么？Claude Code 的 How Claude Code works 页面说：对话历史，文件内容，命令输出，Claude 点 M D，记忆，skill，还有系统指令。我们的 Agent 也一样：系统提示，笔记，每一条消息，每一个工具结果。在我们的测试里，工具结果是最大的一块：读一个文件，我们测到，大约一千个 token。读二十四个，就是两万多。在 Claude Code 里，输入斜杠 context，可以看到一张彩色方格图，看哪一块最占地方。

【2 先数一数】
要管，先得数。数的办法，不是猜，是用 API 每次返回的数字，我们每一轮都打印出来。这里有一个小发现。用 DeepSeek 的接口时，第二次调用，input tokens 只有二百二十五。但窗口其实是一千六百三十三，因为有一千四百零八个，来自缓存。官方的 context windows 页面说，缓存的前缀，也占窗口。所以我们把三个数加起来：新的输入，缓存读取，缓存写入。官方 token counting 页面，还有一个单独的数 token 接口，它说，结果是估算。

【3 先清旧结果】
第一招，最轻：清掉旧的工具结果。Anthropic 的工程文章说，这是最安全、最轻的方式之一。道理很简单：一个工具，很早以前调用过，为什么还要看原始结果？我们的做法：最新的三个结果，原样保留；更早的，换成一句话：旧结果已清除，需要就再调用一次。工具调用本身还在，每个调用，仍然有结果，所以消息的配对不会乱。官方 API 的 context editing 页面，也有类似的功能，叫清除工具结果，目前是测试版。

【4 再压缩】
清掉以后，还是越来越长，怎么办？第二招：压缩。上下文超过线，我们让模型，把旧的几轮，写成一份总结。总结的提示是固定的：任务，做了什么决定，改了哪些文件，还有什么没完成，下一步是什么。最近四轮，原样保留，笔记和文件清单，也一起带上。注意，这份总结，是同一个模型写的，我们不说它和 Claude Code 的一样好。官方 Commands 和 context window 页面说，Claude Code 在接近上限时，自动压缩。总结会保留你的请求，和关键的代码片段，但是早期的详细指令，可能丢失。Claude 点 M D，会从磁盘重新载入。读过或改过的文件，最多重读五个。你也可以输入斜杠 compact，再加几个字，告诉它重点保留什么。官方没有写总结的格式。我们的线，九千到一万二，只是演示，真实的线，要按模型的窗口来定。

【5 真实测试】
来真的跑。四种设置：什么都不管，只清旧结果，只压缩，两个一起。每种跑三次。什么都不管，每次都是二十五轮，峰值大约两万五，三次都答对。只清旧结果，和只压缩，也都是三次答对。两个一起，三次里，答对两次。另一次，跑满了六十轮的上限，没有答案。峰值的范围，看屏幕：清旧结果，八千八到一万一千五；只压缩，一万二千七到一万二千九；两个一起，八千九到一万零九百。三次太少，不能说哪一种最好。这十二次，用的都是第六个坑里，改过的系统提示。

【6 第一个坑：清掉了唯一的记录】
第一个坑，是真实发生的。我们第一次，只清旧结果，模型读到文件链的尽头，却忘了前面找到的待办。因为这些结果被清掉了，而它们，是唯一的记录。它就从头再读一遍，跑了六十轮，没有答案。办法：在系统提示里加一句，旧的工具结果会被清掉，发现了什么，先写在你自己的回复里。加了以后，只清旧结果的三次，都答对了，但有一次，跑了五十三轮才答对。这不是保证。

【7 另外两个坑】
第二个坑，总结会丢决定。我们的测试，没有测到，但官方文档提醒，早期的详细指令，可能丢失。所以长期有效的规则，写进笔记文件，别只在对话里说。第三个坑，一个输出特别大。官方文档说，如果一个输出特别大，总结以后，窗口马上又满。Claude Code 试几次，就会停止自动压缩，并且报错。大输出，要在工具里就截断，这是第二集讲的。

【8 合起来】
这一集，记住四件事。一，数 token，用 API 返回的数，别忘了缓存。二，先清旧结果，最轻。三，再压缩，保留任务，决定，文件，下一步。四，让模型把发现，写在自己的回复里。另外，换一个不相关的任务，官方建议用斜杠 clear，从头开始。子 Agent，在第七集：给它一个新窗口，只带回一份总结。
